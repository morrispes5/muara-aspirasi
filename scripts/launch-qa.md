# Preview launch QA runner

`scripts/launch-qa.mjs` runs synthetic API workflows against this project's Netlify Deploy Preview. It never accepts the production hostname, never changes provider settings, and never reads a database connection string. It is complementary to browser QA, not a substitute for actually using the mobile/student and BEM interfaces.

## Preconditions and execution

Use Node 22 or newer. Apply the current migrations to **Preview**, deploy the current source, and verify the deployed Preview uses its isolated database. `MFA_REQUIRED=true`, `R2_EVIDENCE_ENABLED=false`, and a Preview-compatible Turnstile configuration must already be present. Select an active category UUID from the Preview database. Do not run against a shared production database disguised behind a Preview hostname.

Supply these environment variables through a secure local execution context; do not paste their values into a command log, tracked file, or chat:

| Variable                                                                           | Purpose                                                                                                                                           |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LAUNCH_QA_BASE_URL`                                                               | `https://deploy-preview-4--muaraaspirasi.netlify.app` or another PR Preview for this site                                                         |
| `LAUNCH_QA_ENVIRONMENT`                                                            | Must be `preview`                                                                                                                                 |
| `LAUNCH_QA_ALLOW_PREVIEW_MUTATIONS`                                                | Must be `true`; enables synthetic fixture creation/publication/deletion                                                                           |
| `LAUNCH_QA_CATEGORY_ID`                                                            | Existing active Preview category UUID                                                                                                             |
| `LAUNCH_QA_ADMIN_EMAIL`, `LAUNCH_QA_ADMIN_PASSWORD`, `LAUNCH_QA_ADMIN_TOTP_SECRET` | Existing synthetic ADMIN login with MFA already enrolled                                                                                          |
| `LAUNCH_QA_ADMIN_COOKIE`                                                           | Alternative to ADMIN login variables: an MFA-verified application session cookie                                                                  |
| `LAUNCH_QA_ACCESS_COOKIE`                                                          | If needed, current authorized Netlify Team Protection access cookie; supplied to every request                                                    |
| `LAUNCH_QA_EMAIL_DOMAIN`                                                           | Optional domain allowed by Preview `BEM_ALLOWED_EMAIL_DOMAINS`; defaults to `example.invalid`. No email is sent                                   |
| `LAUNCH_QA_TURNSTILE_TOKEN`                                                        | Defaults to official dummy test token, usable only when Preview is intentionally configured with the test secret. A real token is single-use      |
| `LAUNCH_QA_TURNSTILE_REPLAY_TOKEN`                                                 | Separate fresh real challenge token for the duplicate-submission test; defaults to the initial token for the official repeatable test-secret flow |

Commands:

```powershell
node --check scripts/launch-qa.mjs
node scripts/launch-qa.mjs --self-test
node scripts/launch-qa.mjs
```

The self-test makes no network calls or writes. It checks RFC TOTP vectors and target rejection. The live command creates one report, three short-lived synthetic accounts, two editorial fixtures, and audit/history records. Unique marker plus exact returned IDs scope every cleanup action. Passwords, TOTP seeds, recovery codes, cookies, and receipt secrets remain in memory and never appear in output. Save the non-secret JSON output as QA evidence.

Requests have a 45-second timeout and no implicit retries. A failed request stops dependent tests and runs cleanup. If provider protection returns HTML or a redirect, the failed phase/status is reported without printing that body. Team Protection must be accessed through a legitimately authorized session; changing Preview visibility is a separate owner decision. A passing API run cannot prove an unauthenticated student can access production.

The existing `auth:smoke` is designed for local HTTP: it rejects Secure cookies and does not complete MFA. Do not use it to claim deployed authentication works. The existing `m5:smoke` requires a direct database URL and test Turnstile; this runner intentionally uses the same application APIs as the clients.

## Cleanup and interpretation

On success the synthetic report is deleted through the actual mailbox-request privacy workflow, its tracking credential stops working, both publications are archived, all three newly created users are suspended, and their sessions are revoked by suspension. The supplied administrator and pre-existing UAT report are untouched. Audit events, report tombstone, suspended QA users, and archived content remain intentionally; removal would destroy the evidence being tested.

If an assertion fails, `finally` attempts the same exact-ID cleanup. Draft/review content is left private instead of publishing it just to archive it. Any failed cleanup emits a non-secret ID and marker requiring inspection before rerunning. Do not mass-delete by title prefix. If a network interruption occurs between server commit and a response, report lookup uses the complete unique title. Failed creation of an account/article without a returned ID may require manual lookup by the full marker; never claim cleanup complete without checking this case.

This runner uses two valid submission requests (one receipt and one duplicate) and six tracking requests. Existing limits are five submission attempts per hour per network and eight tracking attempts per code per fifteen minutes. Do not disable the limiter or forge forwarded-IP headers to make QA pass. A 429 is real evidence: let its window reset or use a fresh isolated Preview environment. A rerun creates new fixtures and never resumes or mutates an unrelated historical fixture.

Only the live JSON result proves these deployed checks ran. Local syntax/self-tests prove only the runner's local helper behavior. No live tests are implied by adding this file.
